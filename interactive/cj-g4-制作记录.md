## 电路结构与本案例的教学核心

用户参考图：发射极支路在 R_E 之外多串了一只电阻，C_E 接在**下面那只**电阻两端。

- 标号（用户确认）：上（未被旁路）= **R_E1**，下（被旁路）= **R_E2**。
- **静态**：C_E 对直流开路，两只电阻都计入 → `I_CQ≈I_EQ=(V_BQ−V_BE)/(R_E1+R_E2)`、`V_CEQ=V_CC−I_CQ(R_C+R_E1+R_E2)`。
- **动态**：C_E 只短路 R_E2，**R_E1 仍在交流回路中** → `A_v=−β(R_C∥R_L)/(r_be+(1+β)R_E1)`、`R_i=R_B1∥R_B2∥(r_be+(1+β)R_E1)`、`R_o≈R_C`。
- 这是与案例1（发射极电阻全被旁路）的**唯一本质差别**，也是本页全部关卡设计围绕的教学点。

### 填空与干扰项要点

- **可交换填空全部用 `grp` + `labels` 回填**：`ieq-den`（R_E1+R_E2）、`vceq-res`（R_C+R_E1+R_E2 三空）、`av-den`（r_be+R_E1）、`ri-par`（R_B1∥R_B2）、`ri-den`（r_be+R_E1）。顺序可换、同组不可重复。
- ⚠️ 本页**未使用** `same` 字段——模板引擎只实现了 `grp`（`answerBlank` 的 dup 判定基于 `spec.grp && x.grp===spec.grp && x.picked===id`）。草稿曾写 `same` 但引擎无对应实现，已删除，避免留下"看起来生效其实没生效"的死配置。
- **框架干扰项等价性逐对排查**（制作规范第46轮要求）：
  - A_v：✓ `−β(□∥□)/(□+(1+β)□)` ／ ✗ 分母漏 R_E1 项（案例1 的答案，典型错解）／ ✗ 漏负号。
  - R_i：✓ `□∥□∥(□+(1+β)□)` ／ ✗ 第三支退化为 `□`（案例1 的答案）／ ✗ 并联写成乘法。
  - I_CQ：分子分母结构差异（减/加、缺括号），无等价项。
  - V_CEQ：`□−□·(□+□)` vs `□−□·(□+□+□)` vs `□+□·(□+□+□)` ——括号内项数不同 + 符号不同，互不等价。
- **第4关干扰项设计（本案例核心）**：R_E2 菜单「保留/移除」正确=移除；R_E1 菜单「保留/移除」正确=**保留**。两个发射极电阻的判定完全相反，专门考查"C_E 旁路范围"这一知识点。`execAct` 新增 `re2-remove`（画 `fx-re2` 短接桥 + 收 C_E 支路与 node-emit2）与 `re1-remove`（错答，只扣分不执行）。

## 制作方式：原子补丁脚本（并行会话环境下的必要做法）

本轮没有用「逐个 Edit」改页面，而是写了三个 Python 补丁脚本依次作用于**新文件**（`patchB.py` 区B 电路 / `patchC.py` 注解+引擎 / `patchD.py` 区C·D 配置），每个 `rep()` 都校验「必须命中且全文唯一」，任一不满足立即 `sys.exit(1)`。好处：

1. **可复现**：脚本留在 `.workbuddy/tmp_cjg3/`，页面若被覆盖可一键重建。
2. **不与并行会话打架**：三个脚本都不写 `cj-g3.html`。
3. **匹配失败立刻暴露**：实际踩到两处模板原文与预期不符——`wire-ce-a` 的 data-name 用的是破折号 `—` 不是箭头 `→`；eq 层注释的换行位置不同。脚本逐条报错，比 Edit 静默失败安全。

### 回归脚本自身踩的坑（记录以免下次重犯）

1. **`p.hover('g[data-id=...]')` 常常不触发 mouseenter** —— 组 bbox 中心常落在字形空隙里（例：信号源组中心是圆的空心区）。解法：`hitPoint()` 在组内按 8% 网格扫 `elementFromPoint`，取 `closest('g[data-id]')` 命中该组的点再 `mouse.move`。点击同理。
2. **二级菜单不要再次悬停元件** —— `置零→短路`、`下移→与RB2并` 都是点顶层项后菜单**就地替换**，直接在当前 `#ctxmenu` 里点子项即可（早期版本重新 hover 导致拿到顶层菜单）。
3. **file:// 也会被 Chrome 磁盘缓存** —— 页面改完不生效时先加 `?cb=Date.now()`；本次差点误判"改动丢失"，实为并行会话覆盖 + 缓存两个因素叠加。
4. **覆写 TTS 要用 `Object.defineProperty(window,'speechSynthesis',{get:()=>fake})`** —— 只改原型方法在 headless 下不生效，`say(text, onDone)` 的 onDone 不触发 → 关卡永不推进 → 表现为"点了没反应"。同时要覆写 `window.SpeechSynthesisUtterance`。

### 第63轮（2026-10-11 午）R_E2 矩形点不中 + 先处理 R_E2 报错

用户报两个现象：①整理电路时先处理 R_E1 没问题，先处理 R_E2 就报错；②鼠标移到 R_E2 **文字**上能触发，移到**电阻矩形**上不触发选项。

**根因**——真实通关流程走到第4关「整理电路」时，R_E2 矩形中心的完整命中链是：
```
rect → g#fx-t-re1[data-id=comp-re1] → g#fx-tmodel → g#fx-layer
```
即 **等效态重绘件 `fx-t-re1`（保留的 R_E1）内的 rect 抢走了 R_E2 的点击**。组 `fx-t-re1` 自身 `PE=none`、`opacity=0`，但它的**子 rect** 的 inline `pointer-events` 被 `resetCircuit()` 里那句

（第62轮为解决「重玩后 rarr-rc 不可点」而加）**清空了**，于是子 rect 被引擎自带规则 `.interactive rect[fill="none"]{pointer-events:all}` 重新赋权。

**本轮正解：命中隔离改用独立 class，不依赖会被复位的 inline 样式**
- CSS：`.hit-off, .hit-off * { pointer-events: none !important; }`——写在注释说明处，替换掉上一轮的空说明。
- `hideEl(g)` → `g.classList.add('hit-off')`（不再逐子元素写 inline PE）。
- `showEl(g)` → `g.classList.remove('hit-off')`（原 `unhideChildren()` 已随之删除）。
- `fadeGroup(x, full)` → 半隐/全隐都 `add('hit-off')`（半隐件本就不该可点）。

- 页面初始化扫描、`updateQlabels()` 均改为 add/remove class。
- `.always-clickable, .always-clickable * { pointer-events: all !important; }` 声明在 `.hit-off` **之后**，靠源码顺序让电量标注层（`qlabel-layer`，第2/3关要点它作答）始终可点。

**为什么这次用 class 就不会重演第62轮「CSS 后代选择器误伤兄弟组」**：那个坑来自 `[opacity="0"]` 属性选择器会命中 state-layer 内**任何**带该属性的后代组（隐藏的 `rarr-rb2lab` 把已显示的 `rarr-rc` 一起关掉）。现在 class **只由 `hideEl`/`fadeGroup` 显式写到「被隐藏的那一个组」上**，不匹配属性、也不匹配兄弟节点。
