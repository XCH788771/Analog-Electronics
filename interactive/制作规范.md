### ★ 游戏闯关页统一界面标准（v1.3，2026-10-05 用户定稿；lin-g1~g4 + cj-g1 已统一，新案例必须沿用）

**1）表达式一律「分式（上下式）」书写**（不再用线性式）：

| 写法 | 含义 |
|---|---|
| `tk(main, sub)` | 文本片段（`sub` 为下标，渲染成 `tspan.sub`） |
| `{ box: 1 }` | 虚线框（可作答的空；`ctx.n` 跨行/跨分式连续编号） |
| `fr([分子 tokens], [分母 tokens])` | 分式（上下式）；分子/分母各自排版，中间画分数线 |
| `fitExpr(...)` / `placeExpr(...)` | 放入指定中心点；超宽自动整体缩字（`maxW` 默认面板可用宽） |

> ⚠️ 第 2 关「框架选项」必须**结构上互相可区分**（常数项/运算符/分式不同），否则三个选项视觉相同无法作答。
> ⚠️ `fr()` 参数是**两个 token 数组**，别再套一层数组：`fr([tk('A','v1')], [tk('A','v2')])` ✔；`fr([[tk('A','v1')]],…)` ✗（渲染成 undefined）。

**1a）分式书写补充规则（2026-10-06 用户定稿，所有框架与填空表达式必须遵守）**：
1. **全部上下式**：任何除法一律 `fr()`，禁用线性 `tk('/')`（含干扰项）。
2. **冗余括号一律去掉**：变成上下式后，分子/分母**整体**的括号不再需要（分数线本身已分组）——`RB2/(RB1+RB2)` 写 `fr([R_B2],[R_B1,+,R_B2])`；`(R_C∥R_L)/r_be` 写 `fr([R_C,∥,R_L],[r_be])`。分母**内部**需要的括号保留，如 `r_be+(1+β)R_E`。
3. **相乘因子写在分式后面，不放进分子**：`Vₒ=−(R₂/R₁)Vᵢ` 写 `−fr([R_2],[R_1])·Vᵢ`；`V_BQ=RB₂/(RB₁+RB₂)·V_CC` 写 `fr([R_B2],[R_B1,+,R_B2])·V_CC`（VCC 在分式后，不进分子）。**填空 blanks 顺序必须与虚线框出现顺序一致**（cj-g1 V_BQ 填空：分子 R_B2 → 分母 R_B1/R_B2 → 分式后 V_CC）。
4. **分式垂直对齐**：分数线与同一行相邻文字（`=`、`+`、`1` 等）的**光学中线**水平对齐。实现于 `buildFrac()`：`barY = -size*0.30`，分子基线 `barY−0.26fs`、分母基线 `barY+0.96fs`（fs=size×0.84）。**勿改回**早期 `-0.04`（分式会整体下沉）。
5. **虚线框垂直对齐（2026-10-09 第47轮定稿）**：填空虚框与**等号光学中线（-0.30s）**水平居中对齐（与分式分数线同口径）。实现于 `buildExpr()`：rect `y = -size*0.70`（框高 0.80s → 框心 -0.30s）；`inkExtent()` 的 box 分支同步 `-fs*0.70 / +fs*0.10`。**勿改回**早期 `-0.58`（框会相对等号下沉 0.12s≈4-6px）。fill 关填入的答案按**框几何中心**自适应居中（`renderFill` 的 done 分支），改框位置答案自动跟随。lin-g1~g4 旧引擎只改 rect y（无 inkExtent）。

**2）右面板版式（自上而下，坐标由常量固定，勿改）**：

| 常量 | 值 | 含义 |
|---|---|---|
| `LX / RX / LW / LCX` | 1010 / 1530 / 520 / 1270 | 面板内容左右边、宽、中心 |
| `DIV_Y` | 216 | 分隔线 |

| `BODY_TOP / BODY_BOT` | 334 / 704（lin）；**352** / 704（cj-g1） | 自适应主体区上下沿 |

| `BTN` | {x:1416, y:748, w:114, h:44} | 🔊 提醒按钮 |


### ★ 引擎计分语义（draw 关，勿凭现象改引擎）

- `per = Math.round(c.pts / c.targets.length)`——**只按 `targets` 算**，`subSteps` 里的 `moveIds`（整理电路的下移目标）**只推进子步进度、不给分**。
- `comp-t`（晶体管「等效」）在 `chooseDrawOption` 里走 `t-equiv` 分支**直接 return 不计分**，其分值由等效问答池 `d.tquiz.pool` 在最后一问结算。
- 例：cj-g2 第 4 关 `pts=18`、targets=5 → `per=4`，实际 = C1/C2/Vs/Vcc 四项×4 + 五问池 2 = 18。`pts` 与 `targets.length` 不整除时靠"n 项 × k 分 + 池 m 分"配平。

### ★ 布局设计对齐范式（2026-10-01 lin-g4 第 5 轮定，先算后画，禁止挤牙膏式微调）

横向重排不要一轮挪 10~20（960 宽的图上视觉不可见），一次到位用**约束方程**解坐标：

1. **节点居中范式**：某段导线两端的元件定下后，分支节点取两端 x 的平均值；
2. **电阻居中范式**：「电阻在 A 与 B 之间居中」→ 电阻中心 = (A_x + B_x)/2；
3. **对齐范式**：上下两条水平支路（如 R₁ 分压、R₃ 接地）左端对齐 + 运放两输入端同 x ⇒ 两条支路的节点自动同轴，一处居中处处居中；
4. **减半范式**：用户说"导线长度减半/移到一半"= 新长度 = 旧长度/2，据此反推运放新位置（尖端 = 远端 − 旧长/2）；
5. 改动量按"一眼可见"标准：横向 ≤40 的挪动在整图上几乎不可辨，重排至少 80+；
6. 每轮改完必跑自检脚本 + 截整图，与用户描述逐条对照断言（可用临时 python 断言脚本核验"节点=中点""两电阻同 x"等约束）。

## ★ 第65轮新增规约（2026-10-11）：qorder 多合法顺序 + mix 按路线双方案（cj-g3 首创，引擎在 _patch_g3.py）

- **Playwright 第 7 坑**：本机 headless Chrome 下 **`browser.close()` 会挂起**，整个进程被看门狗 SIGTERM（exit code 1 / Signal SIGTERM），但**此前的工作（截图、断言）均已实际完成**。对策：①结果断言/print 放在 close 之前；②截图脚本直接 `process.exit(0)` 不调 close（进程树随 SIGTERM 一并回收，实测无残留 chrome 进程）；③长任务输出**落盘或用管道**后另起命令读取，勿把后续步骤串在同一条被杀的 shell 里。
