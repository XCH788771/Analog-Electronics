### ★ 游戏闯关页统一界面标准（v1.3，2026-10-05 用户定稿；lin-g1~g4 + cj-g1 已统一，新案例必须沿用）

**1）表达式一律「分式（上下式）」书写**（不再用线性式）：

| 写法 | 含义 |
|---|---|
| `tk(main, sub)` | 文本片段（`sub` 为下标，渲染成 `tspan.sub`） |
| `{ box: 1 }` | 虚线框（可作答的空；`ctx.n` 跨行/跨分式连续编号） |
| `fr([分子 tokens], [分母 tokens])` | 分式（上下式）；分子/分母各自排版，中间画分数线 |
| `fitExpr(...)` / `placeExpr(...)` | 放入指定中心点；超宽自动整体缩字（`maxW` 默认面板可用宽） |

> ⚠️ 第 2 关「框架选项」必须**结构上互相可区分**（常数项/运算符/分式不同），否则三个选项视觉相同无法作答。
> ⚠️ `fr()` 参数是**两个 token 数组**，别再套一层数组：`fr([tk('A','v1')], [tk('A','v2')])` ✔；`fr([[tk('A','v1')]],…)` ✗（渲染成 undefined）。

**1a）分式书写补充规则（2026-10-06 用户定稿，所有框架与填空表达式必须遵守）**：
1. **全部上下式**：任何除法一律 `fr()`，禁用线性 `tk('/')`（含干扰项）。
2. **冗余括号一律去掉**：变成上下式后，分子/分母**整体**的括号不再需要（分数线本身已分组）——`RB2/(RB1+RB2)` 写 `fr([R_B2],[R_B1,+,R_B2])`；`(R_C∥R_L)/r_be` 写 `fr([R_C,∥,R_L],[r_be])`。分母**内部**需要的括号保留，如 `r_be+(1+β)R_E`。
3. **相乘因子写在分式后面，不放进分子**：`Vₒ=−(R₂/R₁)Vᵢ` 写 `−fr([R_2],[R_1])·Vᵢ`；`V_BQ=RB₂/(RB₁+RB₂)·V_CC` 写 `fr([R_B2],[R_B1,+,R_B2])·V_CC`（VCC 在分式后，不进分子）。**填空 blanks 顺序必须与虚线框出现顺序一致**（cj-g1 V_BQ 填空：分子 R_B2 → 分母 R_B1/R_B2 → 分式后 V_CC）。
4. **分式垂直对齐**：分数线与同一行相邻文字（`=`、`+`、`1` 等）的**光学中线**水平对齐。实现于 `buildFrac()`：`barY = -size*0.30`，分子基线 `barY−0.26fs`、分母基线 `barY+0.96fs`（fs=size×0.84）。**勿改回**早期 `-0.04`（分式会整体下沉）。

**2）右面板版式（自上而下，坐标由常量固定，勿改）**：

| 常量 | 值 | 含义 |
|---|---|---|
| `LX / RX / LW / LCX` | 1010 / 1530 / 520 / 1270 | 面板内容左右边、宽、中心 |
| `DIV_Y` | 216 | 分隔线 |
| `SUB_Y` | 312（lin）/ 318（cj-g1） | 固定小字基线（本关操作说明） |
| `BODY_TOP / BODY_BOT` | 334 / 704（lin）；**352** / 704（cj-g1） | 自适应主体区上下沿 |
| `FB_Y` | 732 | 反馈行基线 |
| `ST_Y` | 774 | 状态行基线 |
| `BTN` | {x:1416, y:748, w:114, h:44} | 🔊 提醒按钮 |

顺序：**关卡标题（红）→ 分隔线 → 关卡序号（①…④）→ 固定小字 → 自适应主体区（要求+选项+反馈）→ 状态行**。主体区用 `planRows()`（行高自适应，在可用高度内取尽量大的行高）+ `layoutBody()`（整体垂直居中），避免留白过多/文字过小。

## 一、工作流程（重要：初稿优先）

```
用户提供电路内容 → 复制 _template.html 出初稿 → 用户在独立对话分支中反馈 → 逐轮优化 → 定稿记录
```

1. **初稿一次到位**：用户给出电路内容后，直接按本规范画出完整初稿（图 + 全部交互 + 语音 + 计算推导），不求完美但求完整。
   - **游戏闯关页**：复制 `_game-template.html`（v2，cj-g1 蓝本·两阶段五关）→ 只替换 A/B/C/D 四个「替换区」+ `★换案例` 专属数据点 → 跑布局自检 → 跑自动化通关自检（满分 100）。引擎 / 版式 / 配色一律不动。
2. **每个教学内容一个对话分支**：
   - 新开对话，说"继续优化 XX 电路（lin-lX）"即可——上下文由 `lin-lX-定稿记录.md` + 工作区记忆自动恢复，无需重新解释。
   - 本框架对话只管：模板升级、规范修订、主站入口、全局问题。
3. **交付前必须自查**（见第五节），不要让用户当"人肉质检"。
4. **定稿收尾：更新真实页面截图缩略图**：定稿后用 headless Chrome 截 1280×720 存 `网站/assets/thumb-<id>.png`，并在 data.js 对应案例加 `thumbImg: 'assets/thumb-<id>.png'`——专题页案例卡对已建案例显示真实页面截图（object-fit:cover），未建案例保持简笔示意。命令模板：
   `"C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu --hide-scrollbars --window-size=1280,720 --screenshot="F:\AI建课\模电\WorkBuddy\网站\assets\thumb-<id>.png" "file:///F:/AI建课/模电/WorkBuddy/网站/interactive/<id>.html"`

## 三、绘图规范

- 元件/导线一律包 `<g class="interactive" data-id="..." data-name="...">`，内部图形加 `class="hot"`，文字加 `class="hot-label"`（悬停自动金黄高亮）。
- 线宽 3.5；**元件标注两级字号（2026-10-07 定稿，全站统一）**：元件标注 = **37px**（元件代号 R₁/R₄/C₁/Vᵢ/Vₒ/Vₒ₁/＋−极性/节点字母 B/C/E/β/运放内 A）；电量标注 = **28px**（q-* 电量 VBQ/VBE/IBQ/ICQ≈IEQ/VCEQ 及其＋−、fx-tmodel 的 rbe/i_b/βi_b、lin-l1 计算演示标注 Vp/Ip/Vn/In/I1/I2/Ri/Ro）。小字 20-23；"+"黄色、"−"浅蓝、其余白色。页面标题 43、案例行 36、已知行 26、提示 20、页脚 21、计算过程 46、calc 按钮 34、步骤圆点①②③ 26（勿动）。
- **每个元件和每条导线都是独立交互单元**，无遗漏（自查清单第 1 条）。
- **屏幕标注只保留元件符号**（Vᵢ/R₃/A/Vₒ…），不显示元件编号（如 V1）、不显示公式小注（如 R₃=R₁∥R₂）——避免杂乱压线。
- 输入端 +/− 从运放本体独立出来，各带 `r=26` 隐形热区（`fill="transparent" pointer-events="all"`）。
- **矩形元件（电阻框等 fill="none"）必须内部可命中**：SVG 默认 `visiblePainted` 只认边框，框中间是悬停/点击死区。模板 CSS 已内置兜底规则 `.interactive rect[fill="none"] { pointer-events: all; }`（2026-09-28 lin-g1 踩坑后回灌模板 + lin-l1/lin-t4/lin-g1 四个文件），新页面复制模板自动继承，勿删。
- 演示用图层（箭头、圆点、节点圈）必须加 `pointer-events="none"`，不拦截悬停。
- 节点圆点装饰 `r=7` 白色；演示态绿色节点 `r=11` 盖在上面。
- **★ 下标必须用 `baseline-shift: -20%`，禁止 `baseline-shift: sub` 关键字**（2026-10-01 踩坑）：Chrome 对 SVG tspan 的 `sub` 关键字位移量随字号增大异常放大——60% 时正常，88%/100% 时下标直接被甩到"下一行"错位。**字号统一 75%（2026-10-07 用户定稿：下标比主体小 1/4）**：`tspan.sub { font-size: 75%; baseline-shift: -20%; }`（模板与全部 9 个已建页面已回灌，svg-layout-check.py 的 SUB_SCALE=0.75 与之同步；75% 后注意重排标签避让——如 cj-g1 rarr-rc 标签与 R_L 标签的间隙随下标缩小而变化）。
- **★ 标签避让（2026-10-01 定，数值基准 = lin-g1 实测）**：元件标签墨迹（含 75% 下标下沉 20%）与元件图形**净间隙 14~21px**——横向电阻标签基线 y = 电阻上沿 − 22（≈14px）；端子/侧向标签 ≈ 20px。**大于 30px 即「过空」**（lin-g4 教训：标签悬空显得散，用户点名批评），小于 8px 会压元件（lin-t4/lin-g1 R₃R₄R₅、lin-g3 R₁ 曾压上沿，已修）。**导线不得从「标签与元件之间」的空档穿过**：该空档属于标签，走线绕行（上方绕行留 ≥15px 净空）或改标签位置；绕行形成的 T 形接点补 r=7 白色节点圆点（lin-g4 Vₒ₁ 引出线即为范例）。
- **★ 元件布局均匀（2026-10-01 定）**：元件最近邻净间隙 ≥ 20px、同类元件间距差异 ≤ 1.5 倍——不许一半拥挤一半空洞；**元件两端导线长度尽量接近（比值 ≤ 1.5:1）**，避免一端贴死、一端拖长。违例由自检工具第 ⑦/⑧ 项自动报出。

## 四、语音与文案约定（TTS 踩坑总结，必须遵守）

1. **电压用 V 不用 u**：Vᵢ 输入、Vₒ 输出、V₊=V₋ 虚短（教材惯例，全站长期）。
2. **屏显与语音两套文字**："同相/反相"屏显用"相"，语音稿写"同**向**/反**向**"（纠正 TTS 发音）。
3. **TTS 不读符号**，语音稿全用中文/音译：
   - 音译表：V=威/微，N=恩，P=批，i=埃 → 如"Vn等于Vp等于Vi"写作"威恩等于威批等于微埃"
   - 公式念中文："Av=1+R2/R1" → "电压放大倍数Av，等于1加R1分之R2"
   - 元件名用中文词："Vi"会读成"微埃"，信号源称"输入信号源"
4. **分句播放**（speakSeq）：演示动画写在对应句子的 `onStart` 里，与语音开口精确同步。
5. **语音互斥（calcSpeaking，框架已内置）**：计算推导语音播放期间，悬停其它元件只显示文字注解、不播语音，鼠标移开也不打断演示声画——保证多句推导完整播完。
6. 语音稿语气口语化，一句一个动作。

### ★ 布局设计对齐范式（2026-10-01 lin-g4 第 5 轮定，先算后画，禁止挤牙膏式微调）

横向重排不要一轮挪 10~20（960 宽的图上视觉不可见），一次到位用**约束方程**解坐标：

1. **节点居中范式**：某段导线两端的元件定下后，分支节点取两端 x 的平均值；
2. **电阻居中范式**：「电阻在 A 与 B 之间居中」→ 电阻中心 = (A_x + B_x)/2；
3. **对齐范式**：上下两条水平支路（如 R₁ 分压、R₃ 接地）左端对齐 + 运放两输入端同 x ⇒ 两条支路的节点自动同轴，一处居中处处居中；
4. **减半范式**：用户说"导线长度减半/移到一半"= 新长度 = 旧长度/2，据此反推运放新位置（尖端 = 远端 − 旧长/2）；
5. 改动量按"一眼可见"标准：横向 ≤40 的挪动在整图上几乎不可辨，重排至少 80+；
6. 每轮改完必跑自检脚本 + 截整图，与用户描述逐条对照断言（可用临时 python 断言脚本核验"节点=中点""两电阻同 x"等约束）。
